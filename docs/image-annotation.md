# 图片测试集盘点与辅助标注

本工具将本地图片目录生成 XLSX 和完整 JSON 清单，供人工确认类别、知识价值、处理方式和
关键参考事实。当前交付是辅助标注工具，尚不是已确认的评测基准，也没有评测图片识别方案。

## 使用

在 `E:\personal_KB` 执行，PowerShell 命令直接使用单行：

```powershell
python -m pip install -e ".[annotation]"
python -m wechat_html_normalizer.image_annotation --input test_pictures --output output/image-annotation
```

命令返回新目录，如 `output/image-annotation/annotation-002/`，其中包括：

- `图片辅助标注.xlsx`：实际填写的工作簿，缩略图内嵌，不依赖预览文件或网络；
- `inventory.json`：完整文件身份、元数据、来源关系、扫描异常和统计；
- `previews/`：等比例预览副本，用于核验，不改变原图。

每次运行以排他创建目录的方式选择下一个可用编号，已有目录不会重用。不会读取、覆盖或合并
旧工作簿中的人工数据；中断目录不算完成结果，仅存在 `inventory.json` 且 `status=complete`
才是已完成输出。原图链接使用生成时的本地绝对 file URI，移动输入目录后可能失效，内嵌图仍在。

首次生成后打开工作簿的“标注主表”：

1. 第一遍填写主类型、知识价值、推荐处理；辅助标签用分号分隔，不需要宏。
2. 第二遍只为需要识别的图片补充关键事实，看不清或缺上下文时保留不确定性。
3. 对照原图核对后才选择“已确认”，需要补材料时选择“待补充”。

“填写说明”包含全部下拉选项、按类型的通用处理建议和明确标为示例的参考事实。建议没有自动
写入实际图片的人工答案列。Logo、照片、二维码等没有正文上下文时不自动认定无知识价值。
关键事实基准支持事实覆盖与错误检查，不能直接当作完整 OCR 字符准确率基准。

## 工作簿与浏览限制

- 标注主表：一文件一行，冻结表头及序号、短ID、文件名；蓝色为人工填写区。
- 文件与来源：完整 SHA-256、原始相对路径、格式、宽高、字节数、解码状态、重复组和匹配状态。
- 来源关系：一关系一行；通过完整 imageId 关联，不把多个文档或资产ID挤进一个字段。
- 填写说明：两遍填写流程、选项、示例、审核标准、扫描范围及异常。
- 选项：隐藏的技术辅助表，用于四组下拉验证。

缩略图最大画布为 280×170 像素，行高 138 磅；使用 EXIF 方向校正、等比例缩小和浅灰透明底，
不拉伸，不嵌入全分辨率原图，动画只展示首帧。细节密集或细长图需打开原图阅读。

表头可筛选，图片使用 `twoCell` 随单元格移动锚点。但本轮没有在桌面 Excel/WPS 验证筛选与
排序行为，**请勿排序、插入或移动主表行**；筛选后若图片显示异常，恢复全表并按序号、文件名
与原图链接核对。首次打开请检查表头、下拉和几张原图链接；链接可能需要 Excel/WPS 安全确认。

## 扫描与来源匹配

输入递归扫描所有普通文件，包括子目录、无后缀和解码失败文件；不按扩展名忽略损坏图片。
每个文件独立计算完整 SHA-256，短 ID 只用于显示。同二进制不同文件保留多行，以完整哈希归组。
如果将来划分开发集/保留集，同一重复组应放在同一集合。

拒绝链接文件和输入/输出目录祖先中的符号链接、Windows junction；内部链接目录跳过并在清单
报告。输入与输出禁止互相包含。默认每个扫描根最多 2,000 个文件；图片超过 50 MiB 或
4,000 万像素不生成预览，仍保留哈希及失败行；来源 JSON 上限 10 MiB。文件不可读或扫描不可靠
时明确报错，不发布成功清单。运行末尾再次扫描并逐项复算原图哈希，检查内容与文件集合未变化。

默认来源范围仅为项目输出：`output/documents`、`output/real-samples`、
`output/managed-samples`、`output/real-completion-pair`。不扫描整个磁盘，不进入 `.work`
原始解压缓存。可显式选择输出根，参数可重复：

```powershell
python -m wechat_html_normalizer.image_annotation --source-root output/real-samples --source-root output/managed-samples
```

独立图片无来源也能标注，可用 `--no-source-match` 禁用匹配并记录为未执行。

读取现有 Document 和 ResourceManifest 并以当前严格模型验证。普通正文资产优先复算输出
文件哈希；没有存储哈希时，仅在已声明的输出资产路径内补算，不在本轮额外遍历原始资源缓存。
记录哈希与现存二进制冲突时报告异常，不确认同源，也不从清单降级绕过冲突。

匹配依据分别为：

| method | 依据与局限 |
| --- | --- |
| `verified_binary_sha256` | 测试图片与实际输出资产重新计算的完整哈希一致 |
| `recorded_binary_sha256` | 测试图片与正式记录哈希一致，但输出资产缺失；关系标为 source_missing |
| `manifest_recorded_binary_sha256` | 与资源清单哈希一致；原缓存资源未额外复算，assetId 留空 |

正式文档ID、修订ID和资产ID仅从来源数据读取，旧格式没有修订ID时保持空值。同一文档不同
修订或多个保存目录中的记录均保留证据路径，因此多个匹配不意味着输入文件重复。
未匹配、未执行、来源缺失和多个匹配分别记录；来源扫描异常详见清单和工作簿说明。
没有实现内容相似或感知哈希匹配。

## 实现与依赖

新增 `src/wechat_html_normalizer/image_annotation.py` 独立生成入口及
`tests/test_image_annotation.py`；只在 pyproject 增加 `annotation` 可选依赖，不改正式导入API、
Document/Asset、Schema、ID、修订和 current 行为。README/使用指南增加入口链接。

复用项目 Pillow 11.2.1 和流式 SHA-256；环境已有 openpyxl 3.1.5，声明为
`openpyxl>=3.1.5,<4`（MIT，环境包元数据确认），本轮未安装/升级依赖。
选它是因为现有 Python 环境已具备图片嵌入、下拉、链接及回读验证能力；无需新增 Node 运行时
或手写 XLSX XML。其代价是没有 Excel/WPS 排版引擎，不能验证桌面软件布局及排序兼容；未来
升级需重跑图片锚点与不覆盖测试，当前不依赖超出本轮的功能。

本次 spreadsheets 技能要求的 `load_workspace_dependencies` / artifact 运行时不在可用工具中；
按用户优先复用本地 Excel 能力的要求采用已安装 openpyxl。保留技能的格式、下拉、嵌入图片和
校验要求；没有声称做过完整工作簿渲染。
