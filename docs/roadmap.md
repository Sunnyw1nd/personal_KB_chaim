# 本地产品路线与工作台交接

第十四轮交接更新：最小工作台与正式修订图片桥接已完成（[当前指南](workbench.md)），下方
原工作台交接表是第十三轮计划，不代表现在仍未实现。下一阶段扩TXT/MD/独立图片；运行中取消、
复杂表格编辑、多进程调度、统一可迁移数据根仍未实现，不重开模型/Prompt路线。

## 产品范围

当前：单机Python工具＋只读观察台。目标：个人本地知识工作台，可以导入、查看正文/图片、组织
资料、修改与审核派生信息、检索及引用；之后可增加RAG问答。没有预设多人账号、SaaS、在线
共享、云部署或插件市场。本轮只是整理和规划，以下功能未因写入路线而完成。

第十二轮按用户反馈“细节修改后勉强可接受”收口为可用但需审核；模型结果中的既有pending
状态不擅自改为approved，现存Codex评审也不替代用户确认。不重开Prompt或模型路线实验。

## 下一轮：最小可操作工作台

| 动作 | 已有调用点 | 仍缺的桥接/验收 |
| --- | --- | --- |
| 本地文章导入 | `application.importing.normalize_sample_archives`、`normalizer.normalize_saved_article` | UI路径选择和单机串行任务；失败不中断已完成项 |
| 查看修订/current | `DocumentRecord`、`storage`、`renderer` | 只读目录索引和修订导航；保留旧current规则 |
| 正文图片任务准备 | `Document`、`Asset`、`PreparedImage`、`EnrichmentRequest` | 不依赖inventory/工作簿的正式任务准备；核实同图多位置和上下文选择 |
| 显式外发与受控识别 | 既有策略、legacy/compact runner | UI确认所选图片/最小上下文；后台预算/状态，不调用CLI解析器来编排 |
| 人工审核/修改 | `reviews.set_review`、独立模型结果 | 决定已有；内容修改尚需人工派生记录，不改模型原文或Document权威事实 |
| 恢复与缓存展示 | `compact_runner.rebuild_manifest`、`inspect_cache`、`observer.collect_index` | 只恢复已存证据，展示未知调用/usage；失败与审核否决不能伪装成功 |

建议界面代码在实际选型后新增`src/wechat_html_normalizer/workbench/`，若最终有独立前端构建
才增加顶层`frontend/`。本轮不创建空目录，不选框架。工作台需要的动作编排优先加入现有
`application/`，复杂执行逻辑继续位于原模块；不通过shell重新调用CLI复制状态和错误规则。

下一轮最短验收：导入一个保存页→查看current和旧修订→选一张正文图→无工作簿生成任务→
展示策略/上下文→显式执行或本地fake验证→查看原文与结果→人工决定→缓存/离线恢复可见。
实际模型调用须下一轮另行授权；默认不发请求。

## 后续顺序与进入条件

1. **TXT/Markdown/独立图片**：先扩展Source与定位契约，小型合成夹具证明格式没有被伪装成HTML，
   再接入同一用户操作模块；Markdown不要执行其中脚本或自动下载图片。
2. **Office**：先确认最常见文件类型，分别验证正文、表格、图片和来源定位。不是把所有Office
   格式统一宣称支持。
3. **URL获取/PDF小验证**：各独立试验。URL只管安全获取/快照，复杂PDF先评价布局及阅读顺序；
   成功证据足够才加入导入范围，不将网页登录态或抓取塞入解析器。
4. **组织与检索**：明确标签/目录、人工版本、chunk来源和引用，再选择关键词/向量路线；索引
   可重建，机器待审信息与人工修改状态有明确使用政策。
5. **RAG**：在检索与引用可验证后，作为一种使用入口增加，而不是替代整个工作台。

当前不创建retrieval/rag/api/plugins或数据库占位体系；数据根配置、锁和查询索引只在真实工作台
需求出现时实施。完整职责和兼容迁移见[架构](architecture.md)。
